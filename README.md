# JSON Viewer — frontend

A SolidJS + TypeScript single-page app for formatting, exploring, **comparing**, **sharing** and **de-duplicating** JSON.
It covers the feature set of https://jsonviewer.stack.hu (Text / Viewer tabs, tree with a Name | Value | Type property
panel, search, Paste / Copy / Format / Remove white space / Clear / Load JSON data) and adds Git-style comparison,
short-link sharing, loading JSON from a URL, duplicate detection, OAuth sign-in (Google / GitHub) and a personal history.

The backend (Litestar, `../backend`) is a separate project exposing a REST API under `/api`.

**Core principle:** everything except _history_ and _account_ works **without signing in**, and every pure JSON operation
(format, minify, sort, tree, search, diff, duplicates) works **offline** in Web Workers. A document only leaves the browser
when you explicitly share it, save it to history, load it from a URL (the server fetches it), or turn on "Analyze on server".

## Prerequisites

- Docker with the Compose plugin, **or** Node 20 with pnpm 9 (`corepack enable`).

## Quick start with Docker

1. Start the **backend project first** (`cd ../backend && docker compose up -d --build`). It creates the
   `jsonviewer-net` network that this project joins. (Alternatively run `docker network create jsonviewer-net` once —
   but then start the backend with that network marked `external`, since Compose refuses to adopt a network it did not create.)
2. `cp .env.example .env`
3. `docker compose up -d --build`
4. Open http://localhost:3000.

The container runs **non-root** (`nginxinc/nginx-unprivileged`, listening on 8080, published as `3000:8080`).
nginx proxies `/api/` to `api:8000` using a variable + Docker's resolver (`127.0.0.11`), so it **starts even when the
backend is down** and picks the backend up when it appears; while it is down `/api/*` answers with a JSON
`service_unavailable` error and the footer shows "API offline" (offline features keep working).
`/healthz` returns `200 ok`. Hashed `/assets/*` are cached for a year (`immutable`), `index.html` is `no-cache`,
gzip is on, and the CSP / `X-Content-Type-Options` / `Referrer-Policy` / `Permissions-Policy` headers from the spec are set
(`nginx/security-headers.conf`).

## Local development

```bash
pnpm install
pnpm dev            # Vite on http://localhost:5173, /api proxied to VITE_API_PROXY_TARGET
# or, inside Docker (joins jsonviewer-net, proxies to http://api:8000):
docker compose -f docker-compose.yml -f docker-compose.dev.yml up
```

The dev proxy uses `changeOrigin: false`, so cookies and the OAuth redirect stay on `localhost:5173`.

### OAuth redirect URIs

The browser always talks to **one origin**, so the provider redirects back through the frontend:

| How you run it               | Redirect URI to register at Google / GitHub          | Backend `OAUTH_REDIRECT_BASE_URL` |
| ---------------------------- | ---------------------------------------------------- | --------------------------------- |
| Docker (this project, nginx) | `http://localhost:3000/api/auth/{provider}/callback` | `http://localhost:3000/api/auth`  |
| `pnpm dev`                   | `http://localhost:5173/api/auth/{provider}/callback` | `http://localhost:5173/api/auth`  |
| API alone (no frontend)      | `http://localhost:8000/api/auth/{provider}/callback` | `http://localhost:8000/api/auth`  |

Sign-in is a **full-page navigation** to `/api/auth/{provider}/login?return_to=<relative path>` (never fetch/XHR). The
session is an httpOnly cookie set by the backend; the frontend never sees a token. For unsafe requests it echoes the
`csrftoken` cookie in `X-CSRF-Token`.

### Regenerating the API types

`src/lib/api/schema.d.ts` is generated by `openapi-typescript` and committed. Against a running backend:

```bash
pnpm gen:api        # GET http://localhost:8000/api/openapi.json
```

### The JSON engine

`lib/json/parser.ts` is a hand-written **iterative** RFC 8259 parser producing a flat struct-of-arrays node table
(pre-order ids, `subtreeEnd`, `parent`, `firstChild/nextSibling`, spans of values and keys, line starts). It keeps
**duplicate keys** and **raw number lexemes** (big integers / precise decimals are displayed and re-serialized exactly
as written), reports `{message, line, column, offset}` errors, enforces depth 512 and strips a BOM. The typed arrays are
transferred (not cloned) from the worker. Formatting works from the model, so nothing is rounded. `canonical.ts` and
`path.ts` are tested for **parity with the backend** (shared number/document/path fixtures); `duplicates.ts` returns the
backend's exact response schema (typed from the generated API types) and was cross-checked against a live backend.

## Privacy: what is sent where, what is stored

**Sent to the server only when you do it explicitly:** Share (document + optional title), Load JSON data / `?url=` links
(the URL — the server fetches it; deep links always ask for confirmation first), "Save to history" and automatic history
saving (signed-in users only; toggle _Save to history automatically_), and "Analyze on server" in the Duplicates panel.
Formatting, searching, comparing and duplicate analysis happen locally in Web Workers.

**Stored in `localStorage`** (all access is try/catch-guarded, size-capped): UI settings, the editor draft (skipped above
2 MB), the compare drafts (skipped above ~0.5 MB), the last 10 URLs, and — for anonymous shares — `{slug, title,
created_at, expires_at, delete_token}` so you can delete your own links from this device (the share dialog says so).
Nothing else sensitive is stored; auth is cookie-only.

## Performance budgets (measured with `pnpm test:perf`, Chromium headless, this dev machine)

| Metric                                 | Budget                               | Measured                                                                                                    |
| -------------------------------------- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| Initial JS (gzip), Viewer route        | ≤ 250 KB                             | **236 KB** (Compare / History / Account / Shared and `@codemirror/merge` are lazy chunks)                   |
| Lighthouse desktop (Viewer, empty doc) | P ≥ 90, A ≥ 95, BP ≥ 95              | **100 / 100 / 100** (against `vite preview`, i.e. without nginx gzip/headers)                               |
| Format a 5 MB document                 | < 1 s, no main-thread block > 100 ms | **~360–470 ms** end to end; longest main-thread task **~100 ms** (editor insert is chunked)                 |
| Parse 10 MB in the worker              | < 1 s                                | 10 MB / 984k nodes parsed in **160–290 ms** (Node, same code as the worker)                                 |
| Tree first paint for a 10 MB document  | < 1.5 s after parse                  | **~15–110 ms** after the parse finished                                                                     |
| Scroll in a 200k-row tree              | 60 fps                               | ~984k rows after "Expand all"; median frame **16.5 ms** (p95 ≈ 110 ms on abrupt 8k-row jumps)               |
| Compare two 2 MB documents             | < 2 s                                | **1.4–2.0 s** (worker ≈ 1.0 s; the rest is CodeMirror laying out ~250k-line documents) — close to the limit |

Numbers vary run to run; the compare budget is the tightest one.

## Accessibility

WCAG 2.1 AA colour contrast was verified for every token pair in both themes (all ≥ 4.5:1). Visible `:focus-visible`
rings; every icon-only button has an `aria-label` + tooltip (`title`); dialogs (Kobalte) trap focus, close on Esc and
return focus; menus and tabs follow the WAI-ARIA patterns; the tree implements the ARIA `tree` pattern (`aria-level`,
`aria-expanded`, `aria-selected`, `aria-activedescendant`, Up/Down/Left/Right/Home/End/Enter/`*`); diff colours are
backed by `+`/`−` gutters, labels and counts; `prefers-reduced-motion` and `prefers-color-scheme` are respected.

## Known deviations from the spec

- **Port mapping `3000:8080`** (the spec allows it): the image is `nginxinc/nginx-unprivileged`.
- The tree model stores **offsets into the source text** instead of a separate string table (same transferable
  typed-array shape, no string duplication).
- **Subtree `hash`** is a 64-bit structural hash (not the backend's SHA-256), so the value is not comparable across client
  and server; the groups, counts, sizes, previews and paths are identical (verified on a live backend).
- The structural diff always ignores object key order (that option only affects the normalized **text** diff); arrays are
  compared by index by default (no LCS); `moved` is reported when matching array items by key (`arrayMatchKey`).
- Tooltips are native `title` attributes (plus `aria-label`), not a custom tooltip component.
- The history entry for a comparison is saved on an explicit **Compare** click (not on every auto-recompute).
- Vitest 3 / jsdom 25 are pinned because Vitest 5 / jsdom 31 need a newer Node than the spec's Node 20 image.
